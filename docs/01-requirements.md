# 需求

内容运营人员需要知道某个素材能否进入排期、原时段能否安排、遇到冲突有什么可选方案，以及选定的方案是否真正保存。最小交付是一份可核验的草稿。审核、档期、用户确认、写入结果都有各自的事实来源。

| 场景 | 验收 |
| --- | --- |
| 正常 | 原时段可用，先提案，确认后写入一条草稿 |
| 素材信息不足 | 列出缺失字段并请求补充，草稿数为零 |
| 审核规则拦截 | 返回规则编号和事实依据，草稿数为零 |
| 时段冲突 | 查询满足硬性窗口的备选，说明冲突并等待用户选择 |
| 重复提交 | 相同确认返回原草稿，持久化记录只有一条 |
| 保存失败 | 返回失败，事务回滚，允许重新确认后重试 |

每轮模型决策有步数上限，工具无新进展时返回明确状态。核心运行以合成数据和本地草稿存储为边界。可扩展接入的事件源和权限见方案文档。
